# 两台真机测试方案（BLE 一对一直连 + iroh 跨网兜底）

> 生成：2026-09-13 第二批盲审 B4（全新会话 Agent），基于 fafc7ef/c05a6a5 代码基线。
> 测试基线：Kotlin 66 单测绿；Rust 222 绿。

## 0. 前置条件（最重要）

- **必须用 CI artifact 的 APK**（GitHub Actions「构建调试 APK」产物，含 `libdc_core.so`）。
  - 本机 `~/dc-build/app/outputs/apk/debug/app-debug.apk` 是旧包，**内无 Rust 核心库**：装上去不闪退，但「出示我的码」页显示「本机安全密钥暂不可用」，加好友/聊天全部不可用，极易误判为功能故障。
  - 下载：`gh run download <run-id> -n app-debug`（最新成功 run 用 `gh run list --repo suer781/Mesui --limit 1` 查；`c05a6a5` 的 CI 跑完即可用）
- 两台手机都支持 BLE 5.0（LE Extended Advertising）为佳；见 §3 B2。

## 1. 可测功能与步骤（手机 A / 手机 B）

### F1 权限流程（最容易，先做）
1. 两台首次打开 App → 各自弹权限请求（Android 12+：通知 + 附近设备；Android 8-11：位置权限）
2. 全部允许 → 常驻通知「节点运行中」（Android 13+ 拒通知则无通知栏，服务照跑）
3. 「我的」→「节点服务」→ 状态「运行中」，有节点 ID（前 16 位）
- 通过：无崩溃、服务通知在、节点面板运行中。失败：toast「蓝牙权限被拒绝」→ 系统设置补授权后重开 App

### F2 附近设备发现（BLE 射频双向验证）
1. A：「联系人」→「发现附近设备」→ 开「近场广播」开关（保持开）
2. B：同页「开始扫描」（保持「只看本应用节点」开）→ 列表出现 A 的匿名别名（6 位 hex），标注「本应用节点」，RSSI 负数
3. B 关扫描，交换角色重复
- 通过：双向扫到对方且标注「本应用节点」。失败：列表空/一直扫描中 → 射频不可见（见 §3 B2/B3）

### F3 加好友：出示码/扫码 + 快连 + SAS 双方确认（核心链路）
| A（出示端） | B（扫码端） | 预期 |
|---|---|---|
| 添加好友→出示我的码 | — | A 显示动态二维码「阶段 1/2 · 蓝牙搭线」 |
| — | 添加好友→扫码添加，授权相机对准 A 的码 | B 取景器工作「对准对方的动态码」 |
| 保持屏幕常亮 | 保持对准 3–5 秒（读帧+3 秒防偷拍门槛） | A 提示「阶段 2/2 · 蓝牙已连接」；B 出现安全码卡片 |
| 核对「安全码：XXXXXX」与完整校验串 | 核对同一串 | 两端一致 |
| 点「我确认双方安全码一致」 | 同 | 各自「已确认本端；等待对方确认…」→ 对方确认后「已添加为联系人」 |
| 回联系人页 | 回联系人页 | 列表出现对方，带蓝色「已认证」盾标 |

- 失败：B 一直「等待对方进入蓝牙范围并连接…」→ BLE 链路没建（B2/B3）；B 出现「密钥协商失败」→ 点「重试蓝牙连接」；出现「身份密钥与既有记录不一致」→ 正常安全行为

### F4 数据帧回退路径（可选，验证兼容模式）
A 出示码页保持 8 秒不动（无蓝牙链路自动降级）→ 提示「兼容模式：蓝牙帧与数据帧交替出示」→ B 再扫码保持对准直到出现 SAS 卡片。判定同 F3。

### F5 BLE 近场聊天（飞行模式，WiFi/蜂窝全关）
1. 先完成 F3 配对
2. 两台都开飞行模式，**手动重新打开蓝牙**（保持 WiFi 关）
3. 回联系人页 → 对方在线点变**实心**
4. A 发「你好」→ 右侧气泡 + 时间戳；B 收到左侧气泡
5. B 回一条 → A 实时收到，消息列表出现会话摘要
- 失败：Snackbar「对方不在线（蓝牙不在范围内且远程节点不可达）」→ BLE 链路断；消息静默不出现 → 落库/链路问题

### F6 失败路径：对方不在线
1. B 飞行模式并关蓝牙（或强制停止 B 的 App）
2. A 发消息 → 5–20 秒后（iroh 建连/ACK 超时窗）Snackbar「对方不在线…」，**消息不落库**（重进聊天页无此消息）
3. B 恢复正常，A 重发 → 正常送达
- 失败：无提示（长时间无反馈）/ 显示已发送但 B 没收到

### F7 iroh 同 WiFi 直连聊天（关蓝牙，验证跨网兜底）
1. 两台连同一 WiFi，节点服务「运行中」
2. 两台都关蓝牙（或拉开 10 米以上）→ 在线点变灰
3. A 发消息 → iroh 走 naddr 直连（同网段私网 IP 可达），B 收到；B 回复 A 收到
- 失败：Snackbar「对方不在线」→ 查节点是否运行、是否同网段

### F8 iroh 跨 WiFi / 热点（无中继预期失败 + 可选自建中继）
1. 配对时同 WiFi（保证 naddr 快照正确），完成后 A 留 WiFi-1，B 切热点/另一 WiFi
2. 关蓝牙，A 发消息 → **多数情况 Snackbar「对方不在线」**（naddr 私网 IP 跨网不可路由，RelayMode::Disabled 无中继，打洞通常失败）——这是设计预期，**不是 bug**
3. 若 B 收到 → 打洞成功（记录，惊喜）
4. 可选：自建 iroh-relay 填进「我的→节点服务」保存并重启 → 重复步骤 2 → 消息应送达
- 失败：配置了可用中继仍发不出（查中继 URL 合法性、节点是否重启）

## 2. 判定标准速查

| 功能 | 通过 = | 失败 = |
|---|---|---|
| 权限 | 常驻通知 + 节点「运行中」 | toast「蓝牙权限被拒绝」/ 节点「已停止」 |
| 附近发现 | 双向扫到「本应用节点」 | 列表空 / 一直扫描中 |
| 加好友 | 两端 SAS 一致 → 各自确认 → 「已添加为联系人」→ 认证标 | 一直「等待对方进入蓝牙范围」/ 「密钥协商失败」 |
| BLE 聊天 | 飞行模式+蓝牙双向气泡实时送达 | Snackbar「对方不在线」/ 消息静默丢失 |
| 失败路径 | 明确 Snackbar「对方不在线」，不假送达 | 无提示或假送达 |
| iroh 同 WiFi | 关蓝牙仍双向送达 | Snackbar「对方不在线」 |
| iroh 跨 WiFi | 无中继：明确「打洞失败=需中继」；有中继：双向送达 | 配了可用中继仍发不出 |

## 3. 阻塞点/注意事项

- **B1 关键前置**：本地旧 APK 无 `libdc_core.so`（9/13），必须用 CI artifact 或本地重建（jniLibs/arm64-v8a 已就绪时 `cd /c/Users/13682/dc-chat/android && ./gradlew assembleDebug`）
- **B2 BLE 能力不对称**：布隆过滤器 129 字节超 legacy 31B 上限，依赖 Extended Advertising；代码有 legacy 回退但可能不被对端 extended 扫描器看到 → 快连卡在「等待对方进入蓝牙范围」。对策：优先两台都支持 BLE 5.0；卡住用 F4 兼容模式重试
- **B3 Android 8–11**：必须开系统「位置信息」总开关，否则 BLE 扫描多数机型无结果
- **B4 跨 WiFi 无中继=设计预期失败**，非 bug
- **B5 权限被拒连锁**：拒 BLUETOOTH_CONNECT → 节点服务不起 → BLE/iroh 全不可用
- **B6**：启动即崩溃风险未见必然点；但 B1 的缺 so 包会制造「功能不可用」假象，务必用对 APK

## 4. 建议测试顺序（易→难）

1. F1 权限流程 → 2. F2 附近发现 → 3. F3 加好友+SAS（**最小闭环**）→ 4. F5 BLE 近场聊天 → 5. F6 失败路径 → 6. F7 iroh 同 WiFi → 7. F8 跨 WiFi

每步记录：两台手机型号/系统版本、是否 BLE 5.0、现象（UI 文案截图）、通过/失败。**F3–F5 是最小闭环**——跑通即证明「加好友→SAS→BLE 近场聊天」全链路可用。
