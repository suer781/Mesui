# 去中心化聊天 · 实施方案 v9（已批准，2026-09-04 架构复审修订）

> 第一原则：**绝对 P2P，无中心**。每个客户端 = 服务器 + 客户端（人人即节点）。
> 零强制中心组件：无账号体系、无推送服务、无内置中继、无强制目录服务器、无强制 DNS。
> 发现 = mDNS（局域网）+ **加密介绍信沿联系人链传递**（广域，仅联系人图谱可查）
> + 联系人互相介绍；节点对外用**可轮换临时节点密钥**，不依赖任何公共目录。
> （v8 的「发布到 pkarr/DHT」已废止——见 ARCHITECTURE-RISKS.md A1：那等于
> 全网公开可查「公钥→IP」映射，且实际依赖 n0 中心服务器。）

## 一、自适应负载引擎（自动抉择）

按实时指标自动切换档位，阈值全部可在设置中调整：

| 档位 | 触发条件（默认值，可调） | 自动启用的策略（**只影响传输，不碰加密协议**） |
|---|---|---|
| 轻载（默认） | 群 ≤50 人 且 ≤20 msg/s | 星形直发，单条序列化 |
| 中载 | 群 >50 人 或 >20 msg/s | iroh-gossip 广播树扇出 + 批量打包 + zstd 压缩 |
| 重载 | 上述之上仍劣化 | 分块流式传输 + 心跳降频 + 邀请更多联系人节点分担中继/信箱 |

切换时端到端加密语义不变（同一群内加密协议由建群时定死，见「群聊两类设计」）；
消息 UUID 去重保证通道切换期零丢失、无重复提示。
Go 不进入 App：运行时热切换语言需永久携带双运行时，JNI 边界开销在高负载时放大，
与提速目标相反；自适应诉求由策略引擎实现（算法切换 = 百倍级收益）。

## 二、造轮点清零（全部用现成件）

| 模块 | 现成件 |
|---|---|
| 连接/打洞/中继/传输加密 | iroh 1.1 + iroh-relay（自建服务端；**构建时移除 n0 默认中继与 DNS 发现**） |
| 大群广播扇出 | iroh-gossip（n0 官方，广播树，含模拟器） |
| 端到端加密 | signalapp/libsignal（AGPL-3.0，git 锁 commit）；效率群用 OpenMLS |
| Tor 反封锁 | arti（pt-client/bridge-client），只挂 obfs4/webtunnel 桥 |
| 压缩/序列化/二维码/存储/熵 | zstd / CBOR(ciborium)+分帧 / zxing-android / rusqlite+SQLCipher / getrandom+传感器增强 |

自研仅剩两个小件：通道编排状态机（无密码学胶水）、信封桶信箱（不透明密文桶）。

## 三、人人即节点（v9 修订：身份与发现解耦）

每安装 = 节点（**对外用可轮换的临时节点密钥**，长期 Signal 身份密钥永不进入任何
发现系统；「哪个节点密钥属于哪个身份」只存在于联系人 Signal 会话内）：
信箱桶代存（仅联系人图谱）、联系人间密文中继、mDNS 局域网发现、
**加密介绍信**沿已建立 Signal 会话的联系人链传递当前节点地址。
节点贡献开关/范围/条件/流量上限 + 状态面板。
手机节点为机会性服务；稳定广域中继推荐自建 iroh-relay（互补不替代）。
代价（已接受）：冷启动/换网后首连需联系人链或近场碰面，比公共目录慢。
追踪者最多能跟踪一个轮换周期内的临时节点，无法直接定位人身身份。

## 四、设置中心（十二类子页面）

外观｜通知｜连接与网络（通道优先级/蓝牙参数/中继管理/CDN 前置/严格模式）｜
代理与网络适配（HTTP/SOCKS5 全局与分通道、Tor 桥管理、仅 WiFi、计费感知、一键诊断）｜
节点服务｜自适应策略（档位/阈值/锁档）｜隐私与安全（安全码/应用锁/回执/链接预览默认关）｜
熵源与随机（熵池状态、摇一摇补熵）｜数据与存储｜无障碍（TalkBack/高对比度/多语言）｜高级｜关于

UI：底部导航「消息/联系人/我的」，排版结构参考微信、样式原创，Material You 跟随系统。

## 五、明确不做的事

- **A 密码学与协议层永不自研**（哈希/KDF/签名/棘轮/传输加密/混淆/打洞/发现协议）
- **B** 不做联邦/账号/消息中间件/FCM；不内置公共中继；不在移动端引入第二运行时
- **C MVP 不做**：通话、大文件、语音消息、多设备同步、iOS/桌面、商店分发
- **D 威胁模型诚实边界**：默认模式不承诺元数据匿名；中继运营者可见节点 ID 通信关系不可见内容
- **E 工程红线**：不手写安全敏感代码、不绕权限模型、危险操作二次确认
- **F 节点边界（SP-7 修订）**：不做 VPN/出口代理、不转发非聊天流量；中继开放三档可选（仅联系人/联系人+二度/任何人），「任何人」档 = SP-7 人群转发票 + 三重防重放 + 限额限存，默认关闭
- 哈希全线 BLAKE3 XOF 1024 位（备选 SHAKE256）

## 六、其他关键流程

> 协议规格基线：[SECURITY-PROTOCOL.md](SECURITY-PROTOCOL.md)（信箱门禁 SP-1 /
> 密钥轮换 SP-2 / 二维码信道绑定 SP-3 / 双因子兜底与自毁计时器 SP-4 /
> 中继抗主动探测 SP-5；工程模式移植自微信支付/Telegram 公开文档，先例独立）

- **身份与节点解耦**：长期 Signal 身份密钥只用于身份认证与加解密，永不进入发现系统；
  对外可见的是可轮换临时节点密钥，绑定关系仅存于联系人 Signal 会话内
- 二维码扫码 → 完成添加（零网络依赖，SP-3 v2）：交换长期公钥 + 当前节点密钥/地址。
  （NFC 碰一碰已移除：Android 10+ 移除 Beam、HCE 需用户手动设默认应用，流程不可靠）
  网络添加三因素：端点 + 验证密钥 + 512-bit 热噪声随机数的 1024 位哈希安全码核对
- **群聊两类设计（建群时选类型，不随负载自动切换）**：
  - **隐私群**：永远 pairwise Signal 会话，人数上限默认 50，保留「长按选可见成员，
    未选中者零数据包」
  - **效率群**：OpenMLS 树形加密，无人数硬上限，支持超大群 + gossip 扇出；
    无选择性可见（MLS 语义下做不到，界面不提供该按钮）
  - **隐私群 → 效率群 单向转换（不可逆）**：
    - 由群管理员发起；在线成员即时确认并完成 MLS 加入，离线成员通过信箱
      异步接收转换公告（附 mailbox secret 的 HMAC 证明，同 B1–B5 约束），
      上线时由管理员替其完成 MLS 加入流程
    - 过渡期（尚有成员未入 MLS 树）群消息**双写**：pairwise 逐成员单发与
      MLS 整树加密并存；全员入树或管理员强制 finalize 后结束
      （超时未上线者移除出群）
    - 转换后「选择性可见成员」功能永久丧失（MLS 语义不支持）
    - **不允许反向转换**（效率群 → 隐私群）：技术上旧 pairwise 会话仍在、
      可重建逐成员加密，但反向转换会使元数据重新暴露给中继、功能语义
      反复摇摆，属产品/隐私策略层面的永久禁止
    - 「群管理员」为新增角色，实现前需先补角色定义与权限模型
  - 蓝牙探测稳定切换/断开回退仍适用于两类群（那是通道层的事）
- **近场与信箱协议约束（第二轮复审 B1–B5，详见 ARCHITECTURE-RISKS.md）**：
  - 信箱桶写/读必须附 mailbox secret 的 HMAC 证明（Signal 握手派生，中继只验不读）
  - 节点密钥轮换：公告由长期身份密钥签名推送联系人信箱 + 旧密钥 N 天只读过渡窗
  - 二维码 token 绑定蓝牙/网络信道认证（首条消息带 token 派生确认）+ token 单次有效
  - BLE 广播不含设备名；消息时间戳仅作显示排序，不作安全判定输入
- 蓝牙桥接 ≤6 跳（TTL），互助仅限联系人图谱
