# BLE 多跳中转（mesh relay）设计 v1

> 状态：**设计稿，未实现**。本文回答「蓝牙信号中继中转怎么做」。
> 原则：不发明新原语，全部复用已落地的 mailbox MAC 门禁 / governor 限额 /
> relay.rs 转发票 / FriendLink 匿名邻居发现；只写「胶水层」。

## 一、现有地基（读完代码后的盘点）

| 原语 | 位置 | 对中转的意义 |
|---|---|---|
| `Envelope.ttl_hops / msg_id` | `envelope.rs:31,41` | 信封从第一天就为多跳设计：跳数上限 + 端到端去重 ID |
| mailbox MAC 门禁 | `mailbox.rs`（SP-1） | 写桶必须附 keyed-BLAKE3 MAC，**中继只验 MAC 不解内容**——零知识转发的协议基础 |
| `RelayGovernor` | `governor.rs` | 中继份额/限额令牌桶，防挤兑 |
| `RelayTicket` | `relay.rs`（SP-7） | 陌生人中继的三重防重放票（挑战哈希 + nonce 缓存 + TTL），来源节点钥签名 |
| FriendLink | `friendlink/FriendLink.kt` | 匿名邻居发现：布隆过滤器 + 每日/槽位轮换派生 ID，广播不含任何稳定身份 |
| BleMesh 链路 | `ble/BleMesh.kt` | 已有：命中回连、HMAC 挑战应答、`Wire.MSG` 直发、iroh 兜底、统一解密落库 |

**缺口**：BleMesh 只承载「这一跳邻居自己收的消息」；没有转发帧类型、没有盲转发逻辑、
没有 msg_id 去重缓存、`mailbox_verify` 没有暴露成 FFI、离线信箱代存与队列补投未接线
（`sendText` 注释自认「队列补投为后续阶段」）。

## 二、核心设计：零知识盲转发

### 2.1 消息格式

新增 BLE 帧类型 `Wire.Relay`，载荷 = 完整 `BucketWrite`（envelope + MAC + serial + nonce + 时间戳，CBOR）。
中继者视角的载荷是不透明密文桶——**它不知道也不需要知道目的地是谁**。

### 2.2 中继者的四道闸（收到一帧，顺序执行）

1. **验 MAC**：新 FFI `mailbox_verify(bytes) -> bool`（Rust 侧已有全部材料）。不过 = 门口拒收，不入库不转发。
2. **msg_id 去重**：每节点维护 LRU(512) 已见 ID 缓存；重复 = 静默丢弃（防环路风暴的第一道）。
3. **TTL 递减**：`ttl_hops -= 1`，≤0 丢弃。上限 6 跳（PLAN.md 已定的蓝牙桥接红线）。
4. **限额**：governor 令牌桶，每邻居每分钟 N 帧（默认 30，可配置）；超出丢弃并计数。

四道闸全过后进入投递判定。

### 2.3 「是不是给我的」——用解密能力判定，不用地址判定

中继者**不检查 envelope.recipient**（看了就破坏零知识）。判定方式：

- 对载荷尝试用本机所有已建立会话解密：**解开 = 是我的** → 落库显示，转发终止；
- **解不开 = 不是给我的** → 向当前所有在线 BLE 邻居（联系人图谱内）继续盲投。

这是 Signal 生态 sealed-sender 风格的通行做法：解密能力即投递判定，中继者零知识。
端到端内容安全由 Double Ratchet 保证，中继者拿到的永远是密文。

### 2.4 路由 = 联系人图谱内受控洪泛

**不做路由协议**（PLAN.md 明确：自研仅剩通道编排状态机，不造路由）。
小图 + msg_id 去重 + TTL=6 + 限额，洪泛即可收敛。转发范围红线：
只在联系人图谱内洪泛（PLAN.md F 条），跨图谱边界需要 SP-7 转发票（默认关闭，见 2.6）。

### 2.5 离线怎么办：信箱桶代存

目的地不在线时：把 `BucketWrite` 写到**共同联系人**的桶上（他在线，代存），
目的地回连时拉取。复用 mailbox MAC 门禁；代存节点只看到「有人往某桶写了个加密桶」。
存储上限 + 最旧淘汰走 governor 配置，防代存节点被塞爆。

### 2.6 陌生人中继（跨图谱，默认关闭）

`relay.rs` 的 `RelayTicket` 三重防重放已就绪：逐次握手挑战绑定、nonce 票据缓存、
TTL ≤ 2h、来源节点钥签名。接线即可，**默认关闭**（SP-7 决议），设置页提供开关。

## 四、威胁模型诚实边界（沿用 PLAN.md D/E）

- 中继者可见：密文元数据大小/时序、邻居关系（谁连着我）——**不可见**：内容、收件人身份
- 时间侧信道（中继者可推测消息大致流向）为无线电物理限制，如实接受
- 电池代价：常驻扫描已占空比设计；转发增量负载须受 governor 硬限，默认保守

## 五、v2 增补：人群扩散层（密集场景，如演唱会）

用户提案采纳：epidemic/gossip 扩散模型 + 连接即握手换会话。三个修正把它落到工程上。

### 5.1 「近 100% 连接」的正确姿势：选择性扩散，不是人人互连

- Android GATT 中心角色并发连接上限约 7~20，连接越多越不稳；万人场不可能也不需要全连。
- Epidemic 协议数学：**每设备 fanout k=3~4 + TTL=6**，覆盖概率随轮次指数逼近 1——
  万人密集场几轮内即近似全覆盖。连接数越少，空口越不拥塞，扩散反而越快。
- 邻居选择策略：**联系人槽位优先**（FriendLink 命中回连，走 MAC 门禁）+ **少量随机陌生人槽位**
  （默认 2~3 个，走人群扩散凭证）。两层都是扩散，差别只在准入凭证。

### 5.2 准入凭证必须分层（本轮设计查出的真空缺）

- 联系人层：mailbox MAC（共享秘密只有双方有）——陌生人**验不了** MAC。
- 人群层：**envelope 签名 = 来源轮换节点钥对规范化信封字节的 Ed25519**，任何节点可用
  信封里的公钥直接验。**现状缺口：`Envelope` 没有签名字段（envelope.rs 无 sig）**，
  这是 A0 新增项；`relay.rs` 的签名/验证设施直接复用。
- 匿名性：陌生人路径 sender 本来就是轮换节点密钥（envelope.rs 注释已定义该语义），
  化名随节点密钥轮换周期更替，长期身份永不出外层。

### 5.3 「TCP 式握手」的落点（已有一级半，补齐第二级）

- 联系人链路：FriendLink HMAC 挑战应答（已有）。
- 陌生人链路：RelayTicket 的 challenge/response（已有）——中继先发随机挑战、票内绑挑战哈希，
  本身就是防重放握手。
- **待补**：链路会话密钥 = 每连接 ephemeral HKDF 派生，逐帧轻量认证 + 防跨连接重放；
  「会话令牌更新」由 FriendLink 既有机制承担（每日密钥 + 10 分钟槽位轮换），
  会话期内再做 key evolution（计数器推进）。

### 5.4 密集场景的真正敌人（设计约束由此而来）

1. **空口拥塞**：演唱会 2.4GHz 全挤爆——payload 尽量小、广播间隔自适应、数据走 GATT 不走广播。
2. **扩散风暴**：消息在稠密图里指数回声——msg_id 去重 + TTL + 每邻居限额 + 拥塞退避
   （RSSI 密度感知：邻居越多，转发概率 p 越低，概率洪泛替代确定性洪泛）。
3. **电池**：扫描占空比已有；连接数上限是第一道电池闸。

### 5.5 实施顺序增补

| 步骤 | 内容 |
|---|---|
| A0（新增，最优先） | Rust：Envelope 增加 `sig` 字段 + 节点钥签名/验证 + 单测 |
| A2 增补 | 人群扩散凭证接入：验签过 = 可转发，验签不过 = 丢弃 |
| A2.5 | 随机陌生人槽位（k=2~3）+ 概率洪泛（密度自适应 p） |
| A1~A3 / B / C | 不变，见第三节 |

## 六、电量与负载自适应节流——**已实现于 `governor.rs`**（本文初稿误判为待办，已订正）

实现核对结论（逐项对着代码确认，非文档转述）：

| 设计要求 | 实际实现 | 位置 |
|---|---|---|
| 转发份额硬顶 15% | `STRANGER_SHARE_FULL = 0.15` | governor.rs:13 |
| 电量 <40% 曲线降速 | `BATTERY_CURVE_START=40` → `BATTERY_CURVE_END=5`，smoothstep 连续滑向地板份额 3%（无断崖） | governor.rs:16-18,84-95 |
| 充电中不降速 | `charging → STRANGER_SHARE_FULL` | governor.rs:87 |
| 并发/连接不因节流减少 | `FLOOR_PER_SENDER = 6` 条/分钟**保底**：人数增多时单发送者上限优雅滑向保底，「连接永远保证，质量递减」 | governor.rs:22-23,118-119 |
| 异常输入不涨资源 | `set_load` NaN fail-closed 到最低份额，禁止 fail-open | governor.rs:69-70 |
| 负载双曲线 | ≤0.6 满份额，0.6→1.0 曲线下降（与电量曲线取 min） | governor.rs:19-21,81 |
| 接口 | `set_battery(percent, charging)` / `set_load(f32)`，Kotlin 电池广播/核心线程占用率喂入 | governor.rs:62-70 |
| 令牌桶 | 按发送者分桶，容量=每分钟上限（允许小突发），按时间差补令牌 | governor.rs:24,145 |

与本文初稿的两点差异（以代码为准）：
1. 曲线终点是 **5% 电量 / 3% 份额地板**（我初稿写 15% 电量 / 0.05 因子）——代码版本
   连 5% 电量都保留 3% 中继份额，保证全网不断联，比我提的方案更保守也更正确。
2. 节流不只看电量，还有**负载曲线**（核心线程占用率），两条曲线取 min——多一道保险。
